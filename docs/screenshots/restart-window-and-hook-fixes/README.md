## Things found during the test that the plan did not expect

- **An inherited PROMPT defeats the cmd opt-out.** This agent runs inside Aryan's afterterm, so its environment carries afterterm's cmd PROMPT with the OSC 133 marks, and the harness passed it on. An opted-out cmd still drew marks (12d), and in the main instance every cmd prompt carried the marks twice (`planSpawn` wraps an existing PROMPT). Results were unaffected. The same happens to anyone starting afterterm from a cmd thread inside afterterm. To test the cmd opt-out from inside afterterm, remove PROMPT from the launching shell first.
- **hasChildren comes from the cached process list.** With the window closed, a 15 s ping in an opted-out cmd never showed as a child (12e recording). Opening the window asks for a fresh list, and the row then changed within 3 s. After a command ends, hasChildren can stay true for a while (tab-3, tab-6); prompt marks win, so it only matters for a shell with no marks.
- **The spinner goes before the needs-you state arrives.** While a question or permission prompt is up, the record says `waiting` within a second, the `working` notification clears about 2.5 s later, and the hook's `attention` arrives about 7 s after the prompt. For those 4 to 5 seconds the sidebar shows the chat as quiet. The restart window is right throughout; the sidebar is out of this round's scope.
- **After a turn ends, the record says `busy` for a second or so** (while the Stop hook runs) before `idle`.
- The first Ctrl+C of row 4 went nowhere, because closing the window leaves the terminal without focus (04b). The first try of row 3 sampled before the pause had begun, because starting pwsh and compiling the pause type takes a few seconds (03b). The row 9 stills 09a and 09b were taken a moment after the sampler first found the dialog's text in the buffer, and show the turn still drawing; frames 09c and 09d from the recording show the dialogs. All are named for what they show; `stall.ps1` now prints when the pause really starts and ends.
- **A chat's name can carry a port that is no longer in use.** In 19g the header pill and the sidebar row's pill both read `:8766`, the port then listening, while the thread's name, which Claude gave the chat while its own server ran, still reads "Background HTTP server on port 8765". A first look at that still can take the name for a stale pill. Not a defect in the pills, and outside this round. (A review read the sidebar pill as `:8765`; enlarged, both pills read `:8766`.)
- **A background agent's permission prompt clears the background flag.** In row 6b (b) the agent's ⚠ needs-permission title is an attention title, so it cleared `backgroundTasks` while the agent was still running (22a, 22b). The window still warned, because the record said `waiting`, then `busy`. If a later Claude Code reports `idle` while an agent runs, the row would read "Resumes" after such a prompt.
- The Git Bash captures show Git Bash's default `user@host` prompt.

### Things found during the sandbox run that the plan did not expect

- **The "Updated to 0.16.0" pill was not seen.** The first look at the reopened app came about two minutes after it opened, long after the pill's 6 seconds. Not a finding about the app, only not observed in this run.
- **The resume with the real config ran the real hook.** Without `--setting-sources local` the user settings load, so the production hook script wrote `tab-1.json` into the test app's `claude-sessions` at 16:44:07, three minutes after the update. Everything that proves the record path happened before it, when that folder was empty.
- **pwsh captured the wrong region.** `screenshot-display.ps1` under pwsh got display 2's bounds right once, then reported `2400,0 2400x1350` and captured a shifted region. The same script under Windows PowerShell 5.1 (`powershell.exe -ExecutionPolicy Bypass -File ...`) gave the right `1920,0 1920x1080` every time, and every kept capture was taken that way.
- The empty install folder `%LOCALAPPDATA%\Programs\afterterm-test` stays after the uninstall, as it was before the run. The run's own data folder `%LOCALAPPDATA%\afterterm-test\data` is left too (uninstalling does not remove data).
